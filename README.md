# resid-cbor

CBOR ([RFC 8949](https://www.rfc-editor.org/rfc/rfc8949)) as a format for
[resid-serial](../resid-serial), the serialization framework. Any type that
has `Encode`/`Decode` instances — written by hand or generated by
`resid-derive` — goes to CBOR and back with these.

```resid
import "src/cbor.resid";

Int main() {
    Result(List(Int), SerialError) bytes = to_cbor(Point {.x = 1, .y = 2}) else { return 1; };
    println(f"{cbor_hex(bytes)}");          // a2 6178 01 6179 02
    Result(Point, SerialError) back = from_cbor(bytes) else { return 1; };
    println(f"{back}");                    // Point { x: 1, y: 2 }
    return 0;
}
```

## Entry points

| Call | What it does |
|---|---|
| `to_cbor(T x) -> Result(List(Int), SerialError)` | the bytes |
| `from_cbor(List(Int) bs) -> Result(T, SerialError)` | one value, then `read_end` rejects trailing bytes |
| `to_cbor_hex(T x) -> Result(Str, SerialError)` | the bytes as hex, for logs and tests |
| `from_cbor_hex(Str hex) -> Result(T, SerialError)` | from hex |
| `cbor_hex(List(Int) bs) -> Str` | any byte string as hex |
| `cbor_encoder()` / `cbor_decoder(bs)` / `cbor_bytes(e)` | the raw states, for a caller that threads them itself |

The decoder is self-describing, so `Value`, untagged enums, `flatten`,
`tag` and unknown-field skipping all work over it. The encoder is
deterministic (RFC 8949 §4.1): every head and every float takes the shortest
form that reads back exactly.

## How the data model maps onto CBOR

| Resid | CBOR |
|---|---|
| `Bool` | major type 7, `false` / `true` |
| `Int`, `UInt(64)` | major type 0 / 1, shortest head; the widths 8..32 widen and are range-checked on the way back |
| `Int(128)`, `UInt(128)` | major type 0 / 1 while they fit in 64 bits, otherwise a bignum (tag 2 or 3) |
| `Float`, `Float(32)`, `Float(16)` | half, single or double, whichever is shortest and exact; `NaN` and infinity are rejected when encoding |
| `Str`, `Str(N)` | major type 3 |
| `ByteBuf`, `Bytes(N)` | major type 2 |
| `Unit`, `Option(T)` `None` | null |
| `Option(T)` `Some(v)` | `v` |
| `List(T)`, `Set(T)`, `List(T, N)` | major type 4 (a set in sorted order) |
| `Map(K, V)` | major type 5, sorted by key |
| a record | a map, the field names as text keys |
| a unit variant | its name as a text string |
| a variant with a payload | a one-entry map `{name: payload}` |
| `Result(T, E)` | the enum `Result { Ok(T), Err(E) }`, so above |
| `Dec(N)` | its decimal text |

Indefinite-length arrays, maps, strings and byte strings are never written
but are always read, and a semantic tag (major type 6) is transparent: the
variant or value it wraps is what a typed read sees.

Two shapes are deliberately not recoverable, as in serde: a struct and a
map are one thing on the wire, and so are `Some(v)` and `v`. A `Value`
decoded from CBOR keeps what the bytes said — a map, not a record.

## Tests

```sh
tests/run.sh             # RESIDC=/path/to/residc to pick the compiler
tests/run.sh --update    # rewrite the golden .out files
```

219 checks across six programs: the RFC 8949 Appendix A vectors both ways
(`vectors`), the whole model round-tripping (`roundtrip`), the
indefinite-length and untyped reads (`indefinite`), what bad bytes report
(`errors`), the `Value` tree (`value`), and instances generated by
`resid-derive` (`derive`). `run.sh` builds `resid-derive` from the sibling
checkout and regenerates `tests/model_serial.resid` before compiling.

## Requirements

A Resid compiler with the changes made alongside resid-serial (spec v3.8) —
the same ones resid-serial itself lists. The framework lives in the sibling
`../resid-serial` checkout; `resid.toml` declares it as a dependency for
the manifest tool, and `src/*.resid` import it by path so an ordinary
`residc` build works with no manifest at all.
